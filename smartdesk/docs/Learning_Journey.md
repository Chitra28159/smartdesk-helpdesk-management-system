# SmartDesk – Development Challenges & Learning Journey

## Introduction

SmartDesk is an IT Helpdesk Management System developed using Java 17, Spring Boot, Spring Security, JWT and PostgreSQL.

This project has been an opportunity to strengthen my backend development skills by building an application incrementally while understanding the concepts, architecture and internal execution behind each implementation.

Rather than focusing only on making the application work, I have made a conscious effort to understand why particular technologies, design decisions and implementation approaches are used.

This document captures the technical challenges, questions, debugging experiences and key learnings encountered throughout the development of SmartDesk.

- How do Java collection operations affect entity relationships?
- How does a many-to-many relationship get represented using a mapping table?

### Practical example from RBAC

While implementing role assignment, I explored the following statement:

```java

```

The important questions were:

- What does `adminRole` contain?
- What happens when the role is added to the user's collection?
- Does this operation directly insert a record into the mapping table?
- How does saving the user persist the relationship?

This helped connect Java collection operations, entity relationships and the eventual database representation.

### Key learnings

- JPA relationship mapping.
- `@ManyToOne` and `@ManyToMany`.
- Entity collections.
- Owning and inverse sides of relationships.
- Join tables and foreign keys.
- Persistence of entity relationships.

## 7. Spring Security and JWT Authentication

Security implementation was one of the most conceptually challenging stages of the project.

The main objective was to understand the complete authentication lifecycle rather than simply generate and pass JWT tokens.

### Authentication and authorization

Questions explored:

- What is the difference between authentication and authorization?
- Why did a request return 403 Forbidden?
- Does 403 indicate that authentication succeeded but authorization failed?
- What happens when Basic Authentication is removed?
- If no token is sent, how does Spring Security determine whether a request is authenticated?
- Why do we receive 401 Unauthorized for requests without valid credentials?

### JWT implementation

Questions explored:

- How is a JWT generated after successful login?
- How does the application extract information from a JWT?
- How is the token validated?
- How does the application identify the user from the token?
- What happens when a token is missing, invalid or expired?

### Spring Security internals

Questions explored:

- What is `AuthenticationManager`?
- What is the responsibility of `AuthenticationProvider`?
- What is `DaoAuthenticationProvider`?
- What does `UserDetailsService` do?
- What is `SecurityContextHolder`?
- Why do we use `UsernamePasswordAuthenticationToken`?
- What is the purpose of `OncePerRequestFilter`?
- How does the Spring Security filter chain work?
- What happens after the JWT authentication filter completes?

### Testing and debugging

Explored different authentication scenarios:

| Scenario | Expected behaviour |
|---|---|
| No authentication credentials | 401 Unauthorized for protected endpoints |
| Basic Authentication credentials | Not supported by the current security configuration |
| Valid JWT Bearer token | Authentication succeeds |
| Invalid JWT | 401 Unauthorized |
| Expired JWT | 401 Unauthorized |

An important learning experience was distinguishing authentication from authorization and understanding why the two can produce different HTTP responses.

### Key learnings

- Spring Security filter chain.
- AuthenticationManager and AuthenticationProvider.
- BCrypt password hashing.
- JWT generation and validation.
- Custom JWT authentication filters.
- UserDetailsService.
- SecurityContextHolder.
- Stateless session management.
- HTTP 401 versus HTTP 403.

## 11. Personal Reflection

One of the most valuable aspects of building SmartDesk has been learning to investigate problems instead of simply applying fixes.

Throughout the project, I have tried to understand what happens internally when a method executes, how Spring manages application components, how Java entities translate into database operations, and how an HTTP request travels through the security filter chain.

Some concepts required revisiting multiple times before becoming clear. However, this process helped strengthen my understanding of backend development and the relationship between Java, Spring Boot, databases and security.

SmartDesk is not just an implementation project; it represents my continuous effort to learn, practise, debug and improve my technical skills.

**My focus remains on continuous learning, understanding fundamentals and building reliable backend applications.**
